# tools/backlog – context for Claude

The board (https://github.com/users/simpel/projects/8, kanban, not project 7) and the autonomous `work-backlog` workflow.

## Issues and board
- Every piece of work has an issue. If none exists, create it with the `new-ticket` skill (`node tools/backlog/ticket.mjs create`), which adds it to the board and sets Status, Priority (P0–P2), Size (XS–XL) and Kind (Feature, Bugfix, Codemod, Tech debt, Docs, Test), plus Model (Auto, Haiku, Sonnet, Opus) and Effort (Auto, Low, Medium, High, Extra) when you know better. The creator decides how the work is run; the `work-backlog` run follows the fields.
- Move the card when the work changes state: `Backlog` → `Todo` → `In progress` when work starts → `Done` when merged. `Parked` = the `work-backlog` run could not land the work and pushed it to a `parked/<issues>` branch (linked in the issue comment); fix it there or move the card back to `Todo`. Update with `gh project item-edit` (field ids via `gh project field-list 8 --owner simpel`).
- PRs link the issue with `Closes #NN`. Comment on the issue with what was done if the work is split up or abandoned.
- Every ticket that adds or changes data or behaviour has a **Seed data** section: which files in `packages/core/src/seed/demo/` (data, `seed-*.ts`, `checks.ts`, `reset.ts`) and `docs/demo-seed.md` change, or an explicit "No seed change" with the reason. A ticket is not done until `seed:demo` runs from an empty database with green checks.
- `gh` needs the `project` scope (`gh auth refresh -s project`).

## Autonomous ticket work (`.claude/workflows/work-backlog.js`)
- The workflow picks unblocked `Todo` tickets, up to 3 at a time, and loops until none are left (safety cap 50 batches). It never picks a `source:agent` ticket until a human moves it to `Todo`.
- **Gate first (ADR 0065):** `tools/backlog/gate.mjs` decides before anything starts. Fewer than 3 parallel tickets (or 2 with weight 8) means the run stops and returns `fallback`: use the `work-tickets` skill (one session, one branch, one PR for all tickets). `force: true` skips it, `adopt` skips it.
- **Flow:** each ticket gets its own worktree (`pnpm wt:new t-<N>`, branch `ticket/<N>`, own database), is implemented and verified there, then shipped as a pull request: one commit `<type>: <issue title>` with `Closes #N` (type from Kind, ADR 0060). The run waits for CI on the PR (red CI is fixed on the branch), then **arms GitHub auto-merge** (`arm.sh`, squash) and removes the worktree. It never merges and never pushes to main, which is protected (PR + green checks). A PR that conflicts with main is rebased and re-verified first. It does not wait for CI on main afterwards; it only refuses to start while main is red. A ticket that stays red (checks, CI, tenancy review), conflicts or is blocked is pushed to `parked/<N>`, its PR closed, commented on and moved to `Parked`. A ticket that needs a merged blocker waits for a later run.
- **Paths by Kind** (`PATHS` in the workflow): Feature is the default. Bugfix reproduces first (a failing test, then the fix). Tech debt must not change behaviour or what existing tests assert. Test changes tests only. Docs changes documentation only and runs only lint and check:structure. Codemod is scripted, runs alone and is gated by a residue search for the old names in the ticket's `### Renames`. A `type:decision` ticket drafts a Proposed ADR and opens a PR that is left for a person to accept (never merged by the run). Gates (docs-only, tests-only, ADR file, repro, residue) feed the same fix loop as red checks.
- **Model and effort** (`pickModel`, `pickEffort`): the Model field (Haiku, Sonnet or Opus) wins; Kind Codemod is Sonnet with 3 fix rounds; Size L or XL, `area:auth` and `area:db` are Opus; Sonnet otherwise. Effort (Auto: Docs Low, codemod Medium, Opus, L/XL and risky areas High, else Medium; Extra is the API's xhigh) sets the reasoning effort. The last fix round raises both. A Codemod or XL ticket runs alone, and the log says when the fields look contradictory.
- **Mechanics:** everything deterministic is a script here (`select.mjs`, `gate.mjs`, `prep.sh`, `checks.sh`, `ship.sh`, `ci.sh`, `arm.sh`, `park.sh`, `residue.sh`, `release.sh`; `ticket.mjs` creates tickets) and Haiku only runs them as one-command runners; Sonnet or Opus work only where judgment is needed (implement, fix rounds, conflicts, red CI, tenancy review). `adopt: [N]` continues the worktree of a dead run (`prep.sh --adopt`). Out-of-scope problems the agents notice are filed after each batch as `source:agent` issues in `Backlog`. Never Fable.

## Tests
