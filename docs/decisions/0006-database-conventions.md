# 0006 – Database conventions

- **Date:** 2026-10-13
- **Status:** Accepted

## Context
Okazi has many entities that link to each other across organization and company boundaries. Data must be traceable, recoverable and auditable. IDs must work in URLs, in external systems and in AI tools without revealing counts or ordering.

## Decision
- IDs are cuid2 strings.
- Soft delete: entities are removed by setting `status` (for example `ARCHIVED`), not with `DELETE`. Hard deletes happen only in migrations and by operations staff.
- Every table has `createdAt`, `updatedAt` and `createdBy`.
- The `AuditLog` table logs every mutation: who (`actor` = `user` or `ai`), what (operation), which entity, before and after images, and the conversation ID when the mutation comes from the assistant.
- Every row has `organizationId`. Exceptions are global system tables, for example users and system skills, which are listed explicitly.
- `createdBy` is set by the org-scoped client, not by handlers: `scopedDb({ organizationId, actorId })` requires an actor and forces `createdBy = actorId` on every create (`create`, `createMany`, `createManyAndReturn`, `upsert`) of a model that has the column, and strips it from updates. Core passes the actor's user id, or `SYSTEM_ACTOR_ID` (`system`) for system work. Rows that Better Auth writes itself (outside `scopedDb`) have `createdBy` null.
- `scopedDb` rejects nested relation writes (`create`, `createMany`, `connectOrCreate`, `upsert`, `update`, `updateMany`, `delete`, `deleteMany` inside `data`, an upsert's `create` or `update`) with `ScopeViolationError`, because the forced `organizationId`/`createdBy` and the soft-delete and append-only rules apply only to the top-level model. Only `connect`, `disconnect` and `set` may be nested. Write related rows with their own call.
- Tables and columns follow the Prisma schema in `packages/db`. Migrations run with `pnpm db:migrate`.

## Exceptions
Every exception is listed as a constant in `packages/db/src/scoped/` (`models.ts`, `conventions.ts`). `packages/db/test/conventions.test.ts` checks every Prisma model against them, so a new model that breaks a convention without being listed fails the test.

### Tables without `organizationId` (`UNSCOPED_MODELS`)
`scopedDb` refuses these models. They follow their owner's schema and are exempt from the column, id and soft-delete rules below.

| Kind | Models | Why |
| --- | --- | --- |
| Global (`GLOBAL_MODELS`) | `User`, `Session`, `Account`, `Verification`, `Organization`, `Apikey`, `Jwks`, `OauthClient`, `OauthResource`, `OauthClientResource`, `OauthRefreshToken`, `OauthAccessToken`, `OauthConsent`, `OauthClientAssertion` | Better Auth tables (`auth.prisma`, generated). Identity, sessions, API keys and OAuth are shared across organizations. `Organization.id` is the tenant id. |
| Platform (`PLATFORM_MODELS`) | `SystemLog`, `AiSetting` | Platform tables (ADR 0015), written only by platform code with `getDb()`. |

`Skill` is org-scoped but has a nullable `organizationId`: SYSTEM skills are global rows (`GLOBAL_READ_MODELS`), readable from every organization and writable only by the seeder.

### Ids
- Better Auth generates its own ids (not cuid2) for rows it writes, and its tables have no `@default(cuid(2))`. This applies to every global table, and to `Member`, `Invitation` and `OrganizationRole` rows written through Better Auth.
- When core writes `Member`, `Invitation` or `OrganizationRole` itself, and when the search index writes `Embedding` (raw SQL), the writer passes `createId()` (cuid2). These are `APP_ID_MODELS`.

### Missing convention columns (`COLUMN_EXCEPTIONS`)
| Model | Missing | Why |
| --- | --- | --- |
| `AuditLog` | `updatedAt`, `createdBy` | Append-only. `actorId` records who acted. |
| `Message` | `updatedAt` | Append-only. |
| `Embedding` | `createdBy` | Derived search index, rebuilt from its entity. |
| `Member`, `Invitation` | `updatedAt`, `createdBy` | Better Auth's shape. `Invitation.inviterId` records the inviter; core audits membership changes. |

The global Better Auth tables also lack columns (for example `Organization` has no `updatedAt`). They are generated by the Better Auth CLI and not hand-edited.

### Permitted hard deletion (`HARD_DELETE_MODELS`)
Every org-scoped model is soft-deleted (`SOFT_DELETE_MODELS`), append-only (`APPEND_ONLY_MODELS`: `AuditLog`, `Message`) or listed here:
- `ItemSetup` and `ItemComponent`: replacement sets owned by an item. `item.*` deletes and re-creates the whole set; the audit log records the change on the item.
- `Embedding`: derived index rows, deleted when their entity is archived.
- `Member` (deleted on removal from the organization) and `Invitation` (own `status` lifecycle): Better Auth rows; core audits both.

## Consequences
- Soft delete means all lists and searches must filter on `status`. This is handled in core and in the org-scoped client, not in each query.
- `AuditLog` grows quickly. Retention and pseudonymisation: see 0032.
- cuid2 is a string format, so indexes are larger than for integers. We accept that so IDs stay opaque.
- Whoever writes a new mutation cannot forget audit, because the audit hook lives in core.
- Whoever writes a new handler cannot forget `createdBy`, because `scopedDb` sets it.
- A new model must be classified (org-scoped or a listed exception) before the test suite passes.
