# 0006 – Database conventions

- **Date:** 2026-10-13
- **Status:** Accepted

## Context
Bibi has many entities that link to each other across organization and company boundaries. Data must be traceable, recoverable and auditable. IDs must work in URLs, in external systems and in AI tools without revealing counts or ordering.

## Decision
- IDs are cuid2 strings.
- Soft delete: entities are removed by setting `status` (for example `ARCHIVED`), not with `DELETE`. Hard deletes happen only in migrations and by operations staff.
- Every table has `createdAt`, `updatedAt` and `createdBy`.
- The `AuditLog` table logs every mutation: who (`actor` = `user` or `ai`), what (operation), which entity, before and after images, and the conversation ID when the mutation comes from the assistant.
- Every row has `organizationId`. Exceptions are global system tables, for example users and system skills, which are listed explicitly.
- `createdBy` is set by the org-scoped client, not by handlers: `scopedDb({ organizationId, actorId })` requires an actor and forces `createdBy = actorId` on every create (`create`, `createMany`, `createManyAndReturn`, `upsert`) of a model that has the column, and strips it from updates. Core passes the actor's user id, or `SYSTEM_ACTOR_ID` (`system`) for system work. Rows that Better Auth writes itself (outside `scopedDb`) have `createdBy` null.
- `scopedDb` rejects nested relation writes (`create`, `createMany`, `connectOrCreate`, `upsert`, `update`, `updateMany`, `delete`, `deleteMany` inside `data`, an upsert's `create` or `update`) with `ScopeViolationError`, because the forced `organizationId`/`createdBy` and the soft-delete and append-only rules apply only to the top-level model. Only `connect`, `disconnect` and `set` may be nested. Write related rows with their own call.
- Tables and columns follow the Prisma schema in `packages/db`. Migrations run with `pnpm db:migrate`.

## Exceptions
- Every exception is a constant in `packages/db/src/scoped/` (`models.ts`, `conventions.ts`: `UNSCOPED_MODELS`, `USER_SCOPED_MODELS`, `COLUMN_EXCEPTIONS`, `APP_ID_MODELS`, `HARD_DELETE_MODELS`). `packages/db/test/conventions.test.ts` checks every Prisma model against them, so a new model that breaks a convention without being listed fails the test. The lists are not repeated here because the code is the source.
- Why they exist: Better Auth tables are shared across organizations and generated by its CLI (own ids, own columns); platform tables (`SystemLog`, `AiSetting`, ADR 0015) are written only by platform code; `UserPreference` and `UserSettings` belong to one user across organizations and are pinned to the acting user (ADR 0039, 0046); `AuditLog` and `Message` are append-only; `Embedding` is a derived index; replacement sets owned by an item are hard-deleted and re-created, with the change audited on the item.
- `Skill` is org-scoped with a nullable `organizationId`: SYSTEM skills are global rows readable from every organization and writable only by the seeder.

## Consequences
- Soft delete means all lists and searches must filter on `status`. This is handled in core and in the org-scoped client, not in each query.
- `AuditLog` grows quickly. Retention and pseudonymisation: see 0032.
- cuid2 is a string format, so indexes are larger than for integers. We accept that so IDs stay opaque.
- Whoever writes a new mutation cannot forget audit, because the audit hook lives in core.
- Whoever writes a new handler cannot forget `createdBy`, because `scopedDb` sets it.
- A new model must be classified (org-scoped or a listed exception) before the test suite passes.
